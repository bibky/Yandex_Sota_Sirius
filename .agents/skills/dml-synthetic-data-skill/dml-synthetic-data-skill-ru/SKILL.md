# Синтетические данные для Differential Machine Learning

Инструкция по генерации датасетов для воспроизведения статьи B. Huge, A. Savine, «Differential Machine Learning» (arXiv:2005.02347). Результат — обучающий набор из троек (вход, выплата, потраекторные производные) и тестовый набор с точными ценами и дельтами.

## Когда применять

- нужно воспроизвести эксперименты статьи или сравнить обычную и twin-сеть;
- нужен датасет «состояние рынка → выплата + наклоны» для любой модели и выплаты из этой постановки.

## Что уточнить перед генерацией

Если пользователь не задал, спроси или возьми значения по умолчанию из раздела «Эталонные задачи» и явно напиши, что взял их:

1. задача: колл в Блэке–Шоулзе, корзина в Башелье или своя;
2. режим: выплаты с одной траектории (основной) или точные цены;
3. размеры обучающих выборок и тестового набора;
4. параметры модели и контракта;
5. зерно генератора и формат файлов.

## Два режима из статьи

| Режим | Метка $y$ | Метка $z = \partial y / \partial x$ | Стоимость |
|---|---|---|---|
| выплаты (основной, в духе LSM) | выплата на одной траектории | потраекторная производная выплаты | вся выборка как одна оценка Монте-Карло |
| точные цены | цена, посчитанная численно | греки | один полный расчёт цены на каждый пример |

Дальше описан основной режим. Точные цены используются для тестового набора.

## Как строится один пример (режим выплат)

1. Выбрать вход $x^{(i)}$ — состояние рынка на дату горизонта $T_1$.
2. Из $x^{(i)}$ построить **одну** траекторию до даты выплаты $T_2$ в риск-нейтральной мере.
3. Посчитать выплату $y^{(i)}$ на этой траектории.
4. На **той же** траектории, с теми же случайными числами, посчитать $z^{(i)}_j = \partial y^{(i)} / \partial x^{(i)}_j$ для всех $j$.

Получается одна строка: $x^{(i)} \in \mathbb{R}^n$, $y^{(i)} \in \mathbb{R}$, $z^{(i)} \in \mathbb{R}^n$.

## Обязательные правила

- **Мера.** Участок $T_1 \to T_2$ симулируется строго в модели ценообразования (мера $\mathbb{Q}$). Иначе $y$ и $z$ будут смещены.
- **Распределение входов свободное.** Оно задаёт только область, где аппроксимация будет точной. Допустимо: симуляция от 0 до $T_1$ с завышенной волатильностью, равномерная сетка, последовательность Соболя.
- **Одна траектория на пример.** Можно усреднить антитетическую пару ($N$ и $-N$): так сделано в ноутбуках авторов. Усреднять $y$ и $z$ по одной и той же паре.
- **Производные потраекторные.** Считать аналитически по цепному правилу или через AAD (JAX, PyTorch, TensorFlow). Конечные разности допустимы только для проверки.
- **Непрерывная выплата.** Для цифровых и барьерных выплат потраекторная производная смещена. Такие выплаты нужно сглаживать (так делают авторы), иначе предупредить пользователя.
- **Без нормализации.** Сохранять сырые значения. Нормализация входит в обучение.
- **Воспроизводимость.** Фиксировать зерно и сохранять все параметры вместе с данными.

## Эталонные задачи

Значения «по умолчанию» ниже выбраны для удобства. Где значение взято из статьи, это указано.

### A. Европейский колл, Блэк–Шоулз, один актив

Параметры по умолчанию: $S_0 = 100$, $K = 110$, $\sigma = 0.2$, $T_1 = 1$, $T_2 = 2$, ставка 0, множитель волатильности для входов 1.5.

- Вход: $S_{T_1} = S_0 \exp\left(-\tfrac12 \sigma_1^2 T_1 + \sigma_1 \sqrt{T_1}\, N_1\right)$, где $\sigma_1 = 1.5\,\sigma$.
- Траектория: $S_{T_2} = S_{T_1} \exp\left(-\tfrac12 \sigma^2 \Delta t + \sigma \sqrt{\Delta t}\, N_2\right)$, $\Delta t = T_2 - T_1$.
- Выплата: $y = \max(S_{T_2} - K,\ 0)$.
- Производная: $z = \mathbb{1}\{S_{T_2} > K\}\, S_{T_2} / S_{T_1}$.
- Эталон: формула Блэка–Шоулза со сроком $\Delta t$, дельта $N(d_1)$.

### B. Корзина, Башелье, $n$ коррелированных активов

В статье $n = 7$, обучение на 1 024 и 65 536 траекториях, тест на 1 024 сценариях. Остальные параметры по умолчанию: $S_{0,j} = 100$, веса $a_j = 1/n$, нормальные волатильности $\sigma_j = 20$, попарная корреляция $\rho = 0.5$, $K = 100$, $T_1 = 1$, $T_2 = 2$.

- $L$ — разложение Холецкого корреляционной матрицы, $N \sim \mathcal N(0, I_n)$.
- Вход: $S_{T_1} = S_0 + \sigma \circ (L N_1)\sqrt{T_1}$, при желании с множителем волатильности.
- Траектория: $S_{T_2} = S_{T_1} + \sigma \circ (L N_2)\sqrt{\Delta t}$.
- Корзина: $b = a^\top S_{T_2}$. Выплата: $y = \max(b - K,\ 0)$.
- Производные: $z_j = \mathbb{1}\{b > K\}\, a_j$.
- Эталон: корзина в Башелье нормальна. Пусть $B = a^\top S_{T_1}$, $\sigma_b^2 = \sum_{j,k} a_j a_k \sigma_j \sigma_k \rho_{jk}$, $s = \sigma_b \sqrt{\Delta t}$, $d = (B - K)/s$. Тогда цена $= (B - K)\Phi(d) + s\,\varphi(d)$, дельта по активу $j$ $= a_j\,\Phi(d)$.

## Тестовый набор

- Входы из того же распределения, что и обучающие, с другим зерном.
- Метки — точные цены и дельты по формулам эталона. Если формулы нет, вложенный Монте-Карло: не меньше $10^5$ траекторий на точку, с указанием стандартной ошибки.
- Размер по умолчанию 1 024 точки.

## Формат вывода

Папка с `.parquet` на каждый размер выборки:

| Массив | Форма | Содержание |
|---|---|---|
| `x_train` | $m \times n$ | входы |
| `y_train` | $m \times 1$ | выплаты |
| `z_train` | $m \times n$ | потраекторные производные |
| `x_test` | $m_{test} \times n$ | входы теста |
| `y_test`, `z_test` | | точные цены и дельты |

Рядом — `meta.json`: задача, модель, все параметры, зерно, число траекторий, антитетика да/нет, способ расчёта производных, дата.

Размеры обучающих выборок по умолчанию: степени двойки от $2^{10}$ до $2^{16}$.

## Проверки перед сдачей

1. **Несмещённость.** Для 3–5 фиксированных входов сгенерировать по $10^5$ траекторий: среднее $y$ совпадает с эталонной ценой, среднее $z$ с эталонной дельтой в пределах трёх стандартных ошибок.
2. **Производные.** На 100 строках сравнить $z$ с конечной разностью при тех же случайных числах. Расхождение на уровне ошибки округления.
3. **Структура.** Нет NaN и бесконечностей. Там, где $y = 0$ (вне денег), $z = 0$. Доля траекторий в деньгах указана в отчёте.
4. **Воспроизводимость.** Повторный запуск с тем же зерном даёт побитно те же массивы.
5. **Покрытие.** Гистограмма входов покрывает область, где будет тест.

## Чего не делать

- не симулировать участок $T_1 \to T_2$ в реальной мере;
- не брать $y$ и $z$ с разных траекторий;
- не усреднять много траекторий на пример без явной просьбы (это другой режим, он дороже);
- не обучать модель и не нормализовать данные в рамках этой задачи;
- не выдумывать параметры из статьи: если значения нет в тексте, называть его выбранным по умолчанию.
